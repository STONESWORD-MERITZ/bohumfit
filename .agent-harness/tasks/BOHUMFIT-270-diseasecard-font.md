### ★제외 1건 — Q 배지(12.5px)는 손대지 않는다
`Badge`는 `src/components/ui/Badge.tsx`의 **공용 컴포넌트**로 다른 화면에서도 쓰인다.
크기를 바꾸면 이 태스크 범위 밖 화면까지 영향이 가고, 호출부에서 `className`으로 덮으면
`text-caption`과 `text-[15px]`가 **같은 요소에 공존**해 Tailwind 유틸 출력 순서에 결과가 의존한다
(결정론적이지 않다). 게다가 배지 영역은 267 동결분(`Q1~Q5 판정·기간 라벨·배지 색 규칙`)에 인접한다.
내용이 `Q1` 두 글자라 12.5px에서도 판독 위험이 낮아, **유지하고 사유를 기록**한다.

### ★20px(title) 미사용 — 계층 역전 방지
카드 병명을 20px로 올리면 모바일 화면 요약 헤더(`DisclosureMobileSummary` h2, 20px)와 **동급**이 되어
"카드 하나가 화면 전체 요약과 같은 위상"으로 읽힌다. 그래서 16(body)/15(sub) 두 단만 쓴다.

### 정보 계층 검사 (역전 0)
모바일: 병명 **16 bold** ≥ 판정 상세 **16 medium** ≥ 그 외 **15**.
부가 설명이 병명보다 커지는 경우가 없고, 원래의 대소 관계(`병명 ≥ 판정상세 ≥ 나머지`)가 보존된다.
★단 계층 **간격**은 압축된다(10~15px 5단계 → 15~16px 2단계). 265가 15px를 하한으로 못박은 이상
다른 선택지가 없으며, 굵기(`font-bold`/`font-medium`/기본)와 색(`ink-900`/`ink`/`ink-soft`)이
계층 신호를 그대로 유지한다.

### ★트레이드오프 — 카드 높이 증가 = 한 화면 카드 수 감소
폰트를 올리면 카드가 세로로 길어져 **한 화면에 보이는 카드 수가 줄고 스크롤이 늘어난다.**
- 실측(아래 검증): 대표 카드 기준 텍스트 줄 높이 합이 **약 1.25배**.
- 완화책으로 **접힘 기본값은 그대로 둔다** — 근거 상세(213)·산식(183)은 계속 기본 접힘이라
  펼치지 않은 카드의 증가분은 병명·코드·메타·칩·판정상세에 한정된다.
- ★밀도를 되찾겠다고 **패딩·여백을 줄이지 않는다**(터치 규격·265 간격 토큰 훼손 방지).
- 판단: 고지 결과는 **한눈에 훑는 화면이 아니라 한 건씩 확인해 옮겨 적는 화면**이라,
  카드 수보다 판독성이 우선이라고 봤다. 밀도 회복이 필요하면 별도 태스크(카드 접기 등)로 다룬다.

### 구현 방식
★제1원칙 준수 — **CSS 숨김·미디어쿼리 아님**. `useIsMobile()`(matchMedia ≤767px) JS 분기,
matchMedia 부재 시 데스크톱 폴백. 183 선례("동작이 같아지는 곳에서 억지 분기 금지")와 충돌하지 않는다 —
이 태스크는 **모바일 전용 오버라이드 자체가 목적**이라 분기가 정당하다.

배치 결정(위 하한 가드 실측에 근거):
- **모바일 클래스 정본** → `src/components/mobile/diseaseCardTypography.ts` (신규).
  전 값이 15px 이상이라 265 가드에 **자동 편입**된다 — 가드 우회가 아니라 가드 안으로 들어간다.

  ★같은 폴더에 두면 265 가드가 정당하게 실패하므로 분리했다. 타입이 `Record<Key, string>`이라

## Step 3 — 레이아웃 영향 확인 (★실제 브라우저 실측)

jsdom은 레이아웃을 계산하지 않으므로, **등가 CSS로 재현한 카드**를 레포 밖 임시 서버에 띄우고
실제 Chromium에서 375/390/430px × (데스크톱 px / 모바일 px)로 쟀다. 긴 병명(26자)·긴 기관명
(`가톨릭대학교 서울성모병원 호흡기내과의원`)·긴 진료기간을 넣은 최악 조합이다.

| 폭 | 데스크톱 넘침 | 모바일 넘침 | 카드 높이(데스크톱→모바일) |
|---|---|---|---|
| 375px | **0** | **0** | 325 → **412** |
| 390px | **0** | **0** | 325 → 412 |
| 430px | **0** | **0** | 304 → 372 |

★**오통과 방지**: 같은 프로브에 폭 900px짜리 `nowrap` 요소를 넣자 **593px 넘침을 검출**했다 —
"0"이 측정 실패가 아니라 실제 0이다. 문서 가로 스크롤도 없음(`scrollWidth ≤ clientWidth`).

- **긴 기관명**: `truncate`가 정상 동작해 말줄임된다(clientWidth 132/167 < scrollWidth 296).
  ★착수 시 "flex 아이템에 `min-w-0`이 없어 넘칠 것"으로 의심했는데 **실측으로 반증됐다** —
  `truncate`에 `overflow:hidden`이 있어 flex 자동 최소 크기가 0이 되기 때문이다.
  **그래서 `min-w-0` 같은 레이아웃 보정을 넣지 않았다**(불필요한 수정 0).
- **긴 병명**: 제목 줄이 `flex-wrap`이라 상병코드 배지가 다음 줄로 내려가며 겹침 0.
- **입원기간 회차 줄**(truncate 아님): 3줄로 자연 줄바꿈, 카드 우측 경계 안(778 < 798).
- **배지·칩**: `flex-wrap`이라 폰트가 커져도 줄만 늘고 겹침 0.
- **269b 하단 네비**: 여백 확보는 `Layout.tsx:231`이 `BOTTOM_NAV_HEIGHT + safe-area + 2rem`으로,
  하단 고정 액션 여백은 `DisclosureMobileShell:197`이 `56 + 24`로 **폰트와 무관하게** 잡는다
  → 카드가 커져도 마지막 카드가 가려지지 않는다(구조상 불변).
- ★**카드 높이 1.268배** — Step 2에 적은 트레이드오프가 실측으로 확인됐다.
